# 1024 RPG — Type 03 Design Notes

## Status
**V0.1 POC — PLAYER VS CPU 1024**

Type 03 是獨立核心玩法，不取代 Type 01 / Type 02。

> **同一張 4×4 1024 棋盤，由玩家與電腦輪流操作；合併數字直接轉化成拔河分數。**

## Core rules
- 玩家與 CPU 起始各 1024 分，雙方總分永遠維持 2048。
- 玩家先手。
- 雙方操作同一張標準 1024 棋盤。
- 一次有效移動後正常出生新 Tile。
- 若該次操作有至少一組 Merge，操作者取得「所有合併後數字的總和」，並從對手分數扣除相同分數。
- 實際轉移量不超過對手剩餘分數，因此分數範圍固定為 0–2048。
- Merge 成功者獲得再動一次。
- 有效移動但沒有 Merge：回合交給對手。
- 無效方向不改變棋盤，也視為未合併，交給對手。
- 任一方被壓到 0 分立即敗北。
- 棋盤完全無合法移動時，比較雙方剩餘分數；較低者敗北，相同則平手。

## CPU POC
CPU 不作弊、不預知未來出生 Tile，只從當下合法方向評分：
1. 優先 Merge 得分。
2. 保留空格。
3. 偏好高數字留在邊角。
4. 避免讓棋盤過早塞滿。

CPU 的目的不是完美 AI，而是先驗證「共享棋盤＋得分拔河＋Merge 再動」是否有對戰張力。

## Presentation
- 上方只有一條 2048 總量的拔河計量條。
- 左側代表玩家、右側代表 CPU；分界線依雙方分數平滑移動。
- 棋盤必須提供 Tile 移動動畫、Merge 放大回彈動畫、新 Tile 出生動畫。
- 得分轉移時，計量條與數字同步動畫。
- 清楚顯示目前回合，以及 Merge 後的連續行動。

## POC question
> 共用同一張 1024 棋盤時，「我現在的 Merge 既會搶分，也可能替對手整理棋盤」是否能形成足夠的 PvE 對戰策略？Merge 後再動是否會形成有趣的連擊與逆轉？
